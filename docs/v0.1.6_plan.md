# ManifoldGuard v0.1.6 Plan

Status: development planning

Target theme: make ManifoldGuard easier to try, explain, and trust without
destabilizing the offline-first core.

## Goals

- Keep default regulation offline-first.
- Preserve existing report shapes unless a new flag explicitly opts in.
- Improve CLI ergonomics for first-time users.
- Add small public examples that explain what ManifoldGuard catches.
- Keep embedding-backed behavior optional through the existing extra.

## First bounded pass

Add a friendly `--why` alias for `--explain`.

Why this matters:

- Users naturally ask "why did this block?"
- Existing explanation output is already deterministic and covered by tests.
- The alias improves usability without changing default output or report schema shape.

Example:

```bash
manifold-check \
  --reference "Water is liquid at room temperature." \
  --candidate "Water is not liquid at room temperature." \
  --no-embeddings \
  --why
```

Expected behavior:

- command blocks the unsupported negation.
- text output includes the same explanation lines as `--explain`.
- exit status remains unchanged unless `--fail-on-block` is selected.

## Second bounded pass

Add a short public CLI quickstart and demo corpus.

Why this matters:

- New users need a tiny example set before reading the larger regression corpus.
- The demo should show one safe emit, one blocked negation, and one numeric drift.
- The corpus and quickstart should be wired into docs-quality checks so they stay fresh.

## Third bounded pass

Add the demo flow directly to the README.

Why this matters:

- Many users only read the GitHub front page before trying a tool.
- The README should show `--why`, `--input-jsonl`, and `--format markdown`
  together as the fastest audited demo path.

Expected behavior:

- README points to the quickstart and demo corpus.
- README shows the small demo command without changing any package behavior.

## Candidate follow-up work

- Consider an opt-in top-level `decision_summary` object for JSON reports after the alias has settled.
- Keep larger geometry improvements separate from this usability track.

## Non-goals

- No package release in this planning pass.
- No public API signature changes.
- No default output changes.
- No embedding model downloads in local or CI checks.
- No repo rename or package rename.
