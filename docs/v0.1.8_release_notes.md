# ManifoldGuard v0.1.8 Release Notes

Status: released

Target package: `manifold-guard==0.1.8`

Release date: 2026-08-03

## Summary

Version `0.1.8` hardens offline candidate-pool performance measurement and
removes redundant relation and negation parsing without changing regulation
APIs, emit/block decisions, audit rows, ranking, or optional-embedding policy.

## User and maintainer changes

- Single-clause negation extraction no longer repeats the same segment pass.
- Single-clause positive-relation extraction no longer repeats common helpers
  against identical whole-text and segment inputs.
- Precomputed empty candidate-negation sets are reused instead of reparsing
  non-negated candidates.
- `scripts/benchmark_candidate_pool.py` provides the frozen 257-row scale
  benchmark and a paired baseline/candidate acceptance mode.
- Paired mode alternates execution order, requires exact complete-report
  parity, rejects identical callables, records per-pair deltas, and enforces a
  configurable maximum regression threshold.

## Consolidated performance evidence

All measurements use the frozen
`data/csv_exports/mbt5_exp20_master_candidate_ledger.csv` workload in offline
mode. It contains `257` submitted candidates, `188` unique normalized groups,
and `69` duplicate evaluations avoided by grouping.

| Change | Scope | Before | After | Measured reduction |
|---|---|---:|---:|---:|
| Single-clause negation deduplication | Parser, 188 unique texts | 62.623 ms | 54.084 ms | 13.636% |
| Single-clause positive-relation deduplication | Parser, 188 unique texts | 184.173 ms | 134.400 ms | 27.025% |
| Empty precomputed negation reuse | Full 257-row pool, 16 alternating pairs | 238.674 ms | 208.244 ms | 12.750% |

The independent post-change 10-iteration full-pool run measured a `206.010 ms`
median. The original development baseline recorded `758.628 ms`, but machine
state and laptop upgrades changed substantially during the development cycle;
the difference between those independent runs is therefore not presented as a
release speedup claim. Only the scoped alternating or isolated measurements in
the table are treated as accepted development evidence.

Every optimization comparison preserved extracted relation sets and complete
candidate records. The full-pool comparisons include action, emitted text,
safety decisions, scores, clamps, relations, duplicate diagnostics, selection
status, and ranking.

## Compatibility and boundaries

- Core operation remains offline-first through `--no-embeddings` or
  `use_embeddings=False`.
- Embedding-backed behavior remains optional through `.[embeddings]`.
- No public regulation or token-shock signature changed.
- Performance evidence is machine-specific and limited to the frozen synthetic
  workload; it is not a cross-machine latency guarantee.
- ManifoldGuard regulates against supplied reference structure and is not a
  universal fact checker.

## Release-candidate decision

The checked development evidence warrants a `0.1.8` release candidate because
behavior parity is exact on the frozen workload, the public API is unchanged,
the optional dependency boundary is unchanged, and future performance changes
now have a reproducible paired acceptance gate.
